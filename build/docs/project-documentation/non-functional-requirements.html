Non-Functional Requirements (NFR)

Performance​

  • System response — the total time from beverage selection to the start of brewing/dispensing should not exceed 3 seconds, assuming the cup is correctly positioned.
  • Cup detection — at least 95% detection accuracy for cup presence and position under standard lighting.
  • Cup-position validation — cup alignment is verified in real time before dispensing. If the cup is not detected or not at the required center point, the machine shall not dispense.
  • Liquid-level monitoring — the system detects empty / partially filled / full in real time and automatically stops dispensing when the maximum threshold is reached.
  • CPU load — CPU utilization should remain below 50% during active inference to prevent overheating and ensure stability.
  • Memory footprint — RAM usage must remain under 1 GB to fit the embedded board's constraints.

Reliability & availability​

  • Continuous operation — the system must run continuously for at least 8 hours without performance degradation or thermal throttling.
  • Detection reliability — at least 95% accuracy for classifying cup presence and position under standard lighting.
  • Robustness — the system must function correctly under varying ambient light (150–800 lux), using LDR sensors to adapt triggers accordingly.

Usability​

  • Intuitive interface — a 10-inch touchscreen with clear graphic icons and large buttons to minimize input errors.
  • Visual feedback — real-time feedback (under 1 second) for every interaction, including face/cup detection boxes and brewing progress.
  • User guidance — on-screen instructions help users complete the ordering process without technical assistance.
  • Accessibility — high-contrast (dark) display mode and multi-language support for readability across lighting conditions.

Maintainability​

  • Modular software architecture — the source code uses a custom internal framework that separates application logic from interface components, easing debugging and the addition of new features without disrupting core functions.
  • System updates — the Yocto Linux-based OS supports full system-image updates via SD card or USB, ensuring version consistency across machine units.
  • Diagnostic tools — a dedicated Cockpit/Admin menu lets technicians monitor sensor status, perform camera calibration, and reset factory parameters without disassembling the hardware.
  • Hardware accessibility — a modular mechanical design enables easy replacement of components such as the camera or LDR sensor.

Security​

  • Data privacy — all user preferences are stored locally in an encrypted SQLite database on the embedded board. No sensitive data is transmitted to the cloud or external servers at this phase.
  • Access control — access to system-settings menus is restricted and protected, preventing general users from modifying critical configurations such as water temperature or sensor calibration.
  • Biometric reliability — face recognition uses a minimum confidence threshold of 90% to prevent false positives.

Compatibility​

  • Runs on the Renesas RZ/V2H platform.
  • Peripheral integration via standard Linux V4L2 drivers for USB/MIPI camera modules.
  • Development supported on Ubuntu 20.04+.
